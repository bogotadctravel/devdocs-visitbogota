SEO, rendimiento y seguridad

1. SEO y analítica​

El SEO de una landing one-page debe enfocarse en claridad semántica, metadatos correctos, carga rápida, datos estructurados y medición de conversiones. Al no identificarse un plugin SEO activo en la lista reportada, se recomienda validar si Bricks o el tema están gestionando title, description y Open Graph.

Checklist SEO recomendado​

ElementoEstado / acción recomendada
Title tagDebe incluir BTIF, Bogotá Travel Innovation Fest y Visit Bogotá.
Meta descriptionResumen claro del evento y llamado a participación.
CanonicalDebe apuntar a https://btif.visitbogota.co/ o la URL canónica definida.
Open GraphImagen social optimizada para compartir.
Twitter CardsConfigurar card summary_large_image.
Schema.orgAgregar Organization y Event si aplica por calendario del evento.
Heading structureUn solo H1 principal; H2 para secciones.
Alt textTodas las imágenes relevantes deben tener texto alternativo.
SitemapValidar si WordPress o plugin genera sitemap XML.

Medición con Google Tag Manager​

GTM4WP está activo y debe usarse para estandarizar la medición. Se recomienda implementar eventos con nombres consistentes y documentación de propósito.

Evento sugeridoDisparadorValor para analítica
cta_unete_clickClic en botón Únete al BTIFMide intención inicial de conversión.
form_btif_submitEnvío exitoso del formularioConversión principal.
scroll_50Usuario alcanza 50% de scrollEngagement medio.
scroll_90Usuario alcanza zona de formulario/footerEngagement alto.
menu_anchor_clickClic en enlaces del menú superiorUso de navegación interna.

2. Rendimiento y optimización​

La landing tiene una base técnica favorable para rendimiento: Bricks Builder suele generar HTML más limpio que constructores más pesados, el número de plugins es bajo y el servidor LiteSpeed permite aplicar caché eficiente.

Fortalezas detectadas​

FortalezaImpacto
Solo un plugin activoMenos dependencias y menor carga potencial.
Bricks BuilderConstructor relativamente ligero y orientado a rendimiento.
Tema hijoPermite optimizar sin tocar el tema padre.
Servidor LiteSpeedPermite caché de página y optimizaciones a nivel servidor.
PHP 8.3Runtime moderno.

Riesgos y oportunidades​

TemaObservaciónRecomendación
ImágenesLa landing utiliza muchas imágenes y fondos visuales.Convertir a WebP/AVIF cuando sea posible; definir dimensiones; activar lazy loading.
WP Memory Limit40 MB reportados.Subir a 128M o 256M.
max_execution_time30 segundos.Subir a 180 segundos para edición con builder.
CachéNo se reportó plugin de caché activo.Usar LiteSpeed Cache o caché del servidor.
CSS/JSBricks y estilos personalizados pueden crecer.Minificar en producción y revisar recursos no usados.

Checklist Core Web Vitals​

Para sostener una buena experiencia se recomienda medir la landing con PageSpeed Insights o Lighthouse después de cada cambio grande. Priorizar LCP en la imagen del hero, CLS en bloques visuales y INP en interacciones del formulario y sliders.

3. Seguridad y operación​

La seguridad del sitio depende de mantener actualizado WordPress, Bricks y plugins activos, limitar usuarios con permisos altos y evitar ediciones directas en producción sin respaldo.

ÁreaBuena práctica
ActualizacionesActualizar Bricks y GTM4WP primero en entorno de pruebas.
BackupsRealizar backup completo antes de actualizar tema o WordPress.
UsuariosAplicar mínimo privilegio: editores no deberían tener permisos de administrador si no lo necesitan.
Editor de archivosDeshabilitar edición de archivos desde wp-admin en producción si existe flujo Git/FTP.
GTMControlar quién puede publicar etiquetas para evitar scripts no autorizados.
FormulariosActivar protección anti-spam si el formulario queda expuesto públicamente.

Riesgo de actualización de Bricks​

La interfaz indica una actualización disponible para Bricks. La actualización debe planearse con backup previo y revisión visual posterior, ya que los constructores visuales pueden introducir cambios de renderizado, CSS o compatibilidad con elementos personalizados.
